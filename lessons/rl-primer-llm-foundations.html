LLM Foundations

You built a GPT in nanoGPT, so you own the core: an LLM is one function predicting the next token, over and over. This primer re-anchors that, then fills the two gaps the RL course leans on — what a modern transformer adds beyond nanoGPT, and the three training stages that turn a raw predictor into the policy you optimize.

01 The input layer

Tokens aren’t words (or letters)

nanoGPT used character tokens. Real models use subword tokens (BPE-style): frequent character sequences get merged into single units, so common words are one token and rare ones split into pieces. It’s a compromise — a pure character vocab makes sequences too long; a pure word vocab is too big and can’t spell.

Why you, the RL person, care The vocabulary is your action space — recall “token = action.” Vocab size sets how many discrete actions the policy chooses among (~100k+), and token counts are what you pay for in compute and what the reward is computed over. Tokenization is the boundary between text and the model’s actual alphabet.

03 Filling the gap

What a modern model adds beyond nanoGPT

nanoGPT is a GPT-2-era design. The open models you’ll actually do RL on — Llama, Qwen, Mistral — keep the exact same skeleton but swap four components for efficiency and length-generalization. Worth recognizing by name:

LayerNormRMSNormsame job, cheaper — drops the mean-centering and bias

The unifying theme None of these change what the model computes conceptually — it’s still attention + MLP on a residual stream predicting the next token. They’re the engineering that makes it train stably, handle long context, and generate fast. If nanoGPT clicked, you already understand 90% of a Llama; this table is the other 10%.

04 The course connection

The base-vs-instruct distinction matters for your build A base model just continues text — ask it “What is 2+2?” and it might continue with more questions. An instruct/SFT model answers. When you start an RLVR experiment you almost always begin from an SFT/instruct checkpoint, because the policy needs to already produce answer-shaped completions for the verifier to score anything useful.

05 Generation

Sampling is how rollouts happen

The forward pass gives a distribution; decoding turns it into text by repeatedly sampling and appending. The knobs control how adventurous that sampling is:

the decoding knobs temperature — scale logits before softmax: T→0 = greedy/argmax · T>1 = flatter, more random
top-k — keep only the k highest-prob tokens
top-p — keep the smallest set whose probability sums to p (nucleus)
The RL tie-in you can’t skip GRPO needs a group of different completions per prompt — that diversity comes entirely from sampling with T > 0. Greedy decoding (T=0) would return the same answer every time and collapse the group, killing the advantage signal. Exploration in LLM-RL is the sampling temperature. One more thing: generation is sequential and the KV cache grows with length, which is why long rollouts get slow and memory-bound — and why GQA exists.

06 Quiz · three

Check yourself

Q1 SOLVE Why does an LLM fumble “how many r’s in strawberry?” — and what does that reveal about its true input? ▸

The model never sees letters — it sees token IDs. “strawberry” arrives as a couple of subword tokens (e.g. straw + berry), each a single opaque vector. The character composition isn’t directly available; to count letters the model has to have memorized spelling facts during training, not “look” at the word. So character-level tasks are inherently awkward.

The deeper point: the token vocabulary is the model’s real alphabet — the same vocabulary that, in RL, is your action space. Reasoning about characters means reasoning about something below the model’s atomic units.

Q2 SOLVE During generation, why is producing the 1000th token costlier than the 10th — and how does GQA help? ▸

Each new token attends to all previous tokens, whose keys and values are stored in the KV cache. At token 1000 the cache holds 999 entries per layer per head; at token 10 it holds 9. The cache grows linearly with sequence length, so memory and bandwidth — not raw compute — become the bottleneck for long generations. Generation is sequential and memory-bound.

GQA shrinks that cache: instead of every query head storing its own K/V, groups of query heads share one K/V head. Fewer K/V copies → smaller cache → faster, cheaper long-context decoding, with negligible quality loss. This is exactly why long RL rollouts (think long chain-of-thought) are expensive, and why inference-efficiency tricks matter for the rollout phase.

Q3 SOLVE A base model and an SFT model both get “What is 2+2?”. How do their outputs differ, and where does the RL you studied act? ▸

The base model is a pure continuer — it predicts what text typically follows that string in its corpus. It might continue with more quiz questions (“What is 3+3? What is 4+4?”) or a worksheet, because that’s a plausible continuation. It doesn’t “answer” because it was never taught that prompts expect responses.

The SFT model has been fine-tuned on (instruction, response) demonstrations, so it has learned the chat format and replies “4.” RL (stage 3 — RLHF or RLVR) then operates on that SFT policy: it samples completions, scores them with a reward or verifier, and shifts the distribution toward preferred or correct answers. RL doesn’t teach the format — SFT does that — it sharpens and aligns behavior on top. That’s why RLVR runs start from an instruct checkpoint, not a base model.

Takeaway

An LLM is one next-token function — attention and MLPs on a residual stream — wrapped in tokenization at the front and sampling at the back. Modern models just swap in faster components; three training stages turn the raw predictor into the policy you optimize. That policy is where your whole RL course lives.
