PPO for LLMs → GRPO

Two moves and you’re at the frontier. First, PPO becomes RLHF almost without edits — a token sequence is just a trajectory. Then GRPO does something bold: it deletes the critic you spent Rung 4 building and replaces it with a baseline you already met in Rung 3. The course closes into a loop.

01 Move one

PPO becomes RLHF without new theory

Everything from Rung 4 maps straight across. A token sequence is a trajectory: the prompt is the start state, each generated token is an action, the running context is the state. The policy is the LLM; the critic is a value head on the same transformer; advantages come from GAE over token positions.

Two LLM-specific wrinkles, both already foreshadowed:

per-token reward in rlhf-ppo // every token: a small leash toward the reference
rt = − β·KL( π_θ(·|st) ‖ π_ref(·|st) )
// last token only: add the reward-model score
rT += R(prompt, completion)

The real reward is sparse — it lands once, at the end. The per-token KL penalty is the leash from the map lesson, keeping the policy language-shaped so it can’t drift into gibberish that games the reward model.

The pain point that motivates move two That critic is hard to train. It has to predict expected final reward at every token position from a signal that only arrives at the end — a noisy regression target on a model as big as the policy. A bad critic gives bad advantages. People wanted it gone.

02 Move two · the frontier

GRPO: the group is the baseline

Recall Rung 3: any action-independent baseline keeps the gradient unbiased while cutting variance, and the ideal one is V(s) — the average return from this state. GRPO’s insight: don’t learn that average, estimate it by sampling. For each prompt, draw a group of G completions, score them all, and let the group’s mean be the baseline.

group-relative advantage — no critic anywhereÂi = ( Ri − mean(R₁…R_G) ) / std(R₁…R_G)
// every token in completion i inherits this single advantage

03 The loop closes

The frontier is Rung 3 again

Strip the notation and look at what GRPO actually is: push up the log-prob of completions that beat the group average, push down the ones that don’t, clip the step so it’s safe. That’s REINFORCE-with-a-baseline — the very first thing you learned — wearing PPO’s safety harness. The learned critic and GAE were a detour you can now remove.

Honest caveats — the things papers argue about Three real ones. (1) You pay for the deleted critic in rollouts: G samples per prompt instead of one — fine for verifiable reasoning, where you sample a lot anyway. (2) Vanilla GRPO gives every token in a completion the same advantage — coarse credit assignment; token-level and process-reward variants address this. (3) The mean/std normalization introduces subtle biases (length, difficulty) that recent work — e.g. “Dr. GRPO” — picks apart. You’re arriving exactly where the live debates are.

04 Why it’s a big deal

Reasoning emerges, it isn’t programmed

Here’s the result that defines the era. Take RLVR (reward = “is the final answer correct?”) and run GRPO at scale. Nobody tells the model to think step by step. But because longer deliberation raises its hit rate, the reward gradient pushes it to deliberate — and chain-of-thought, self-correction, and backtracking appear on their own.

DeepSeek-R1-Zero, in one line Pure RL from a base model — no supervised reasoning examples — was enough to induce all of this, including spontaneous “wait, let me reconsider” moments. A small supervised cold-start was added later only to make the output readable. The reasoning itself came from RL.

05 Check yourself

One exercise

In a GRPO group of G=8 completions to one math prompt, the verifier marks all 8 correct (every R=1). What advantage does each completion get, and what does the policy learn from this prompt on this step? What does that imply about which prompts are useful?

SOLVE Reveal the answer ▸

All rewards equal → the group mean is 1, so every R_i − mean = 0, so every Â_i = 0 (and the std is 0, which implementations guard against). Zero advantage → zero gradient. The prompt teaches nothing this step.

The implication is sharp: GRPO only learns from prompts where the group disagrees — some right, some wrong. Too-easy prompts (all correct) and too-hard prompts (all wrong) are dead weight. This is why curriculum and difficulty-filtering matter so much in practice, and why the baseline being relative to the group quietly builds in a focus on problems right at the model’s current frontier.
